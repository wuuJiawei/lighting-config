# lighting-config 设计文档

> A lightweight & high-performance configuration center for Java services.
> 双形态：可独立部署（Server + Client）与可嵌入（Embedded Dependency）。
> **核心模块不耦合 Spring**，默认提供 Spring Boot Starter 以开箱即用。

---

## 1. 设计目标

* **轻量高性能**：gRPC 长连接推送 + 本地缓存，毫秒级动态刷新。
* **双形态**：

    * Standalone：独立部署 `lighting-config-server` + 业务侧使用 `lighting-config-client`。
    * Embedded：业务项目直接依赖 `lighting-config-embedded`，内置最小化配置中心能力。
* **存储多样**：**默认数据库**（MySQL / PostgreSQL / Oracle 等方言）为权威存储；可选 **Redis** 作为二级缓存；客户端有 **本地缓存**。
* **框架解耦**：`lighting-config-core` 提供协议、领域模型、SPI；不依赖 Spring。Spring 支持以 Starter 实现。
* **易运维**：支持 Docker / Docker Compose 一键启动；提供健康检查、指标、日志。
* **安全可控**：Token/JWT、TLS、命名空间与租户隔离、审计日志。
* **可扩展**：SPI 插件化存储/鉴权/灰度发布策略；易扩展多语言 SDK。

## 3. 模块与源码布局


### 3.1 关键包（core）

* `api`：关键接口（如 `ConfigRepository`、`AuthProvider`、`GrayReleaseStrategy`、`EventBus`）
* `model`：领域模型（`ConfigItem`、`Namespace`、`App`、`Revision`、`AuditLog`）
* `dto`：跨层数据对象（与 REST/gRPC 解耦）
* `spi`：Service Provider 接口（提供默认实现与扩展点）
* `util`：工具（序列化、校验、版本号生成、时间戳）

## 4. 配置模型与数据结构

### 4.1 核心概念

* **Tenant（可选）**：多租户隔离（可默认 single-tenant）。
* **Namespace**：环境/空间隔离（如 `dev/test/prod` 或 `org/app/env`）。
* **App**：应用/服务标识（`app_id`）。
* **ConfigItem**：键值配置，带版本与元信息。
* **Revision**：变更历史（审计）。
* **Tag/Label**：用于灰度/分组（机房、版本、区域等）。

### 4.2 逻辑约束

* `(tenant, namespace, app_id, key)` 唯一确定一个配置项。
* 值支持：`string`、`json`、`yaml`、`properties`（以 `content_type` 存储）。
* 版本语义：`long` 自增（Storage 保证）；可扩展语义版本（如 `1.2.3`）。

## 5. 存储设计

### 5.1 抽象 & SPI

```java
public interface ConfigRepository {
  Optional<ConfigItem> get(String tenant, String namespace, String appId, String key);
  List<ConfigItem> list(String tenant, String namespace, String appId, @Nullable String prefix);
  void upsert(ConfigItem item, String operator);
  void delete(String tenant, String namespace, String appId, String key, String operator);
  long currentVersion(String tenant, String namespace, String appId, String key);
}
```

> `lighting-config-core` 仅定义接口与模型；具体实现放在 server 层（基于 JPA/MyBatis/JOOQ 均可），并通过 `ServiceLoader` 注册，或由 Spring Boot Starter 自动装配。

### 5.2 数据表（RDBMS）

以通用 SQL 表示（注意方言差异：PG/Oracle 自增 & 索引语法不同，提供 Liquibase/Flyway 脚本多方言支持）：

```sql
-- config_item
id BIGINT PRIMARY KEY AUTO_INCREMENT,       -- Oracle: use SEQUENCE + TRIGGER
tenant VARCHAR(64) NOT NULL DEFAULT 'default',
namespace VARCHAR(128) NOT NULL,
app_id VARCHAR(128) NOT NULL,
key VARCHAR(512) NOT NULL,
content_type VARCHAR(32) NOT NULL DEFAULT 'text',
value CLOB NOT NULL,                        -- MySQL: TEXT/LONGTEXT; PG: TEXT; Oracle: CLOB
version BIGINT NOT NULL,
tags VARCHAR(1024) NULL,                    -- JSON string of labels
enabled BOOLEAN NOT NULL DEFAULT TRUE,
created_at TIMESTAMP NOT NULL,
updated_at TIMESTAMP NOT NULL,
UNIQUE (tenant, namespace, app_id, key)
```

```sql
-- revision (审计)
id BIGINT PRIMARY KEY AUTO_INCREMENT,
tenant VARCHAR(64) NOT NULL,
namespace VARCHAR(128) NOT NULL,
app_id VARCHAR(128) NOT NULL,
key VARCHAR(512) NOT NULL,
version BIGINT NOT NULL,
op VARCHAR(32) NOT NULL,                    -- UPSERT/DELETE
operator VARCHAR(128) NOT NULL,
diff CLOB NULL,                             -- 存储变更差异
created_at TIMESTAMP NOT NULL,
INDEX (tenant, namespace, app_id, key)
```

### 5.3 Redis（二级缓存，按需开启）

* Key 设计：`cfg:{tenant}:{ns}:{app}:{key}`
* TTL：可配（默认 5–10 分钟），更新时主动失效或异步刷新。
* 一致性策略：**以数据库为权威**，更新路径：**DB 成功** → **发布事件** → **清理/更新 Redis** → **推送客户端**。

## 6. 缓存与一致性

### 6.1 服务端

* 读路径：`Local (Caffeine) → Redis(可选) → DB`
* 写路径：`DB` 成功后 → 发布 `ConfigChangedEvent` →

    * 失效 `Local/Redis`
    * 通知 `NotifyEngine` 推送更新

### 6.2 客户端

* 启动 **Pull** 一次全量/按需拉取 → 本地缓存（内存，必要时落盘文件）
* 维持 gRPC `Watch` 流：收到 `ConfigUpdate` → 更新本地缓存 → 回调监听器 → 可选热刷新（Spring 环境刷新等）
* 断线重连：指数退避 + 上次版本号校验（必要时发起 **增量拉取** 或 **小全量**）。

## 7. 接口设计

### 7.1 gRPC（lighting-config-link / `config.proto`）

```proto
syntax = "proto3";
package lighting.config;

service ConfigService {
  // 订阅某 app 的变更，支持 namespace / labels 过滤
  rpc Watch(WatchRequest) returns (stream ConfigUpdate);
  // 拉取（单个或前缀）
  rpc Pull(PullRequest) returns (PullResponse);
  // 上报客户端实例心跳（可选）
  rpc Heartbeat(HeartbeatRequest) returns (HeartbeatResponse);
}

message WatchRequest {
  string tenant = 1;
  string namespace = 2;
  string app_id = 3;
  map<string, string> labels = 4;  // 机房、版本、区域等
  map<string, string> meta = 5;    // 客户端环境信息
}

message ConfigUpdate {
  string key = 1;
  string value = 2;
  string content_type = 3;
  int64 version = 4;
  bool deleted = 5;
}

message PullRequest {
  string tenant = 1;
  string namespace = 2;
  string app_id = 3;
  oneof selector {
    string key = 4;       // 精确 key
    string prefix = 5;    // 前缀匹配
  }
}

message PullResponse {
  repeated ConfigUpdate items = 1;
}

message HeartbeatRequest { string app_id = 1; }
message HeartbeatResponse { string status = 1; }
```

### 7.2 REST（Admin & 简易访问）

* `GET /api/config?tenant&namespace&appId&key/prefix`
* `POST /api/config`（创建/更新）
* `DELETE /api/config`
* `GET /api/revisions`（审计）
* `POST /api/gray/release`（灰度策略）
* `GET /actuator/health` / `/metrics`（如启用 Spring Boot）

### 7.3 Spring Boot Starter（client）

```yaml
lighting:
  config:
    server:
      address: "dns:///lighting-config-server:9090"
      connect-timeout-ms: 2000
      tls: false
    client:
      tenant: default
      namespace: prod
      app-id: order-service
      banner-enabled: true
      bootstrap:
        pull-prefixes: [ "datasource.", "feature." ]
      cache:
        file-backup: true
        path: ./config-cache
```

使用方式：

```java
@EnableLightingConfig  // 仅启用监听与注入
@SpringBootApplication
public class OrderApp {}
```

注入配置：

```java
@LightingValue(key = "feature.toggle.new-price", defaultValue = "false")

```

或监听变更：

```java
@LightingListener(prefix = "feature.")

```

## 8. 双形态运行

### 8.1 Standalone

* 运行 `lighting-config-server`（内含 REST + gRPC）
* 业务服务引入 `lighting-config-client`（或 Spring Boot Starter）

### 8.2 Embedded

* 业务服务引入 `lighting-config-embedded`
* 启动时根据 `lighting.config.mode=embedded` 初始化本地 `ConfigRepository`（可用 file/embedded-db）
* 可选对外暴露 gRPC/REST（embedded as server）

## 9. 安全（AuthN/Z）与多租户

* 认证：`AuthProvider` SPI（默认 Token；可扩展 JWT/OAuth2）
* TLS：gRPC 双向/单向 TLS 可配
* 授权：按租户 / 命名空间 / app_id 进行 RBAC
* 审计：`revision` 表记录操作者、diff、时间
* 速率限制：REST 管理 API 支持限流（如令牌桶）

## 12. 失败与恢复策略

* **客户端断线**：指数退避（最大 30s），恢复后带上 lastVersion，比对差异后补齐。
* **服务端重启**：`ClientSessionManager` 重建订阅；对订阅队列做幂等处理。
* **缓存失效风暴**：随机抖动 + 单飞（singleflight）抑制穿透。
* **DB 不可用**：降级为 Redis 兜底读取（可选）、只读模式；**写操作暂停**并报警。
* **Redis 不可用**：不影响正确性，仅影响读取延迟。

## 13. 测试策略

* **Core**：纯 Java 单测（模型、SPI、事件总线）
* **Server**：仓库集成测试（H2/PG/MySQL/Oracle 容器化），Liquibase/Flyway 校验
* **Client**：gRPC 模拟服务 + 断线重连 + 大量变更压测
* **E2E**：Compose 环境跑端到端功能
* **兼容性**：JDK 17+，Spring Boot 3.x（默认），非 Spring 场景通过 core + client 直接接入

## 14. 性能指标（建议目标，持续验证）

* 单节点推送吞吐：≥ **10k updates/min**（小 payload）
* 客户端更新延迟：P99 ≤ **50ms**（内网）
* 拉取 QPS：≥ **2k/s**（Redis 命中 80%+）
* 连接数：单节点 gRPC **10k** 长连接（取决于内核/FD/Netty 参数）

## 17. 开发者接口示例

### 17.1 Server 端保存/推送（伪代码）

```java
// 保存
var item = ConfigItem.of(tenant, ns, app, key, value, "yaml");
repo.upsert(item, operator);

// 通知
eventBus.publish(new ConfigChangedEvent(item));

// 监听事件并推送
@Subscribe
public void onChanged(ConfigChangedEvent e) {
  notifyEngine.push(e.toUpdate());
}
```

### 17.2 Client 订阅与监听（纯 Java）

```java
LightingClient client = LightingClient.builder()
        .serverAddress("dns:///lighting-config-server:9090")
    .tenant("default").namespace("prod").appId("order-service")
    .build();

client.watch(update -> {
  cache.put(update.getKey(), update.getValue());
  listeners.fire(update);
});
```

### 附录 A：关键非功能需求清单（NFR）

* 可用性：单实例支持热升级（优雅停机 + 连接迁移）
* 可靠性：服务端异常恢复不丢事件（基于版本校验的补偿拉取）
* 伸缩性：无状态 Server（存储在 DB/Redis），可水平扩展
* 兼容性：JDK 17+；Spring Boot 3.x（默认），非 Spring 以纯 client 接入
* 安全性：TLS、Token/JWT、审计
* 可运维性：Metrics/Health/日志标准化、Compose 快启
